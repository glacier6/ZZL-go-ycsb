### 1.2 极端并发 (T=32) Load QPS 下降分析

从 3000w 开始, T=32 的 Load QPS 反而低于 T=16:
```
         heatLSM T=16  heatLSM T=32  降幅    Normal T=16  Normal T=32  降幅
3000w:     30,731        29,175      -5.1%     36,421       36,325      -0.3%
5000w:     25,294        24,705      -2.3%     25,750       29,231     +13.5%
7000w:     31,724        27,845     -12.2%     29,821       24,758     -17.0%
9000w:     28,524        24,788     -13.1%     24,900       24,561      -1.4%
```

**heatLSM 在 ≥3000w 数据量下 T=32 QPS 全面下降 2-13%**, 这是因为:
1. 32 线程同时写入造成 L0 快速膨胀 (NumLevelZeroTables=5 频繁触发 stall)
2. Compaction 线程不够用 (NumCompactors=4) → 写入被 back-pressure 阻塞
3. 建议: 大规模 Load 使用 T=16, 或增大 `badger.num_compactors`

**Normal 在 5000w 下 T=32 反而提升 13.5%**, 可能是特定数据分布下 compaction 压力较小。

### 1.3 单线程 Load QPS 随数据量下降

| 数据量 | heatLSM T=1 | Normal T=1 |
|--------|------------|------------|
| 1000w | 14,080 | 15,673 |
| 3000w | 14,354 | 15,020 |
| 5000w | 13,507 | 14,139 |
| 7000w | 12,121 | 12,553 |
| 9000w | 11,762 | 11,697 |

降幅约 17%, 原因是更大的 LSM-tree 导致每次写入时 compaction 概率增加。

   这两组 compaction 收敛异常好, 三轮结果一致(非噪声), 值得关注其 LSM 状态

### 4.4 GC 结论

```
指标              heatLSM        Normal        heatLSM优势
────────────────────────────────────────────────────────
额外物理写(均值)    ~663 MB       ~1,203 MB     少写 45%
回收空间(均值)      ~2,505 MB     ~1,915 MB     多回收 31%
效率(回收/物理写)   ~3.78x        ~1.59x        2.37倍
```

**heatLSM GC 效率是 Normal 的 2.37 倍**，原因分析:

1. **热力树冷热分离**: heatLSM 把热数据集中在热力层 (L98/L99), 冷数据层中热数据少,
   更新操作更集中在冷数据层 → 冷层 Vlog 垃圾率更高 → GC 回收效率更高

2. **GC 物理写更少**: heatLSM GC 时需要重写的有效数据更少 (因为垃圾更集中),
   所以额外物理写只有 Normal 的 55%

3. **Vlog 前大小相近但回收更多的空间**: heatLSM 从 ~35GB Vlog 中回收 ~2.5GB (6.9%),
   Normal 从 ~34GB 中仅回收 ~1.9GB (5.5%)

### 4.5 GC 逐轮趋势

两版本都呈现相同规律: 第1轮回收最多, 第3轮回收最少, 体现边际效益递减:

```
heatLSM tv3000w 单轮回收趋势:  860 → 816 → 777 MB (逐轮下降 5-6%)
Normal tv3000w 单轮回收趋势:   638 → 627 → 614 MB (逐轮下降 2-4%)
```

3 轮 GC 后总回收量约占 Vlog 前大小的 4-7%, 说明仍有大量垃圾未回收
→ 建议增大 `gc.count` 或降低 `gc.discard_ratio` 阈值以触发更多回收。

## 六、总结

| 维度 | heatLSM vs Normal | 结论 |
|------|------------------|------|
| **Load QPS** | Normal 略高 3-8% | Load 不是瓶颈, 差距可接受 |
| **Run QPS (低并发)** | Normal 高 2-10% | T≤4 时 Normal 占优 |
| **Run QPS (高并发)** | heatLSM 高 2-9.5% | **T≥16 时 heatLSM 反超** |
| **P99.9 尾延迟** | heatLSM 低 5-46% | **heatLSM 尾延迟全面优于 Normal** |
| **写放大 (WA)** | heatLSM 低 10-23% | **核心优势, 全配置无一例外** |
| **GC 效率** | heatLSM 高 2.37x | **少写 45%, 多回收 31%** |
